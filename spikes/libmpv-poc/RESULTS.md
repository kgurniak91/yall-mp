# libmpv in-window PoC: benchmark results

Machine: i7-9700K (8C/8T), RTX 2080 Ti, Windows 10, 2405x1344 backing canvas (1600x900 window at 120 DPI), 3 runs per cell (median), 10 s warm-up + 60 s window.
mpv 20261017 (dde0671072) for both legacy (`mpv.exe --wid` into a frameless child window, the app's flags) and libmpv (D3D11 render API, 3 slots).
Generated by `node bench/run-bench.js`; raw JSON is in `results/raw/` (gitignored). `real-*` = the user's Hi10P h264 anime episode with embedded ASS (mpv subtitle rendering ON in every mode). hwdec `auto` falls back to software for it (d3d11va has no 10-bit h264).

Caveats
- Legacy loads **no page**, so it carries no Chromium/Angular cost; the real legacy app has a live UI window on top. Legacy is therefore a lower bound.
- "app CPU" = all processes of the spike tree (electron main/GPU/renderer, mpv.exe in legacy). % of one core = 100 means one full core.
- dwm CPU reads 0 in every cell (sampler tick too coarse), so it is not usable. GPU 3D % includes Chromium's own GPU process.
- Frame-drop counters were 0 in every cell, vo-delayed 0, avsync max < 1 ms everywhere.

## Reference: the real current app (stacked windows, mpv 0.41 `--wid`, live Angular UI)
Measured with `node bench/real-app.js` (same sampler, 3 runs each, 10 s warm-up + 60 s; the app's own window ~1538x839, not the spike's 1600x900; the app's default is hwdec off, "auto" = Hardware acceleration setting on). The spike's legacy column above has no Chromium page, so this is the fair baseline for the gate.

| media / hwdec | real app (% of one core) | of which mpv.exe / electron | spike shared-texture (2d) | ratio |
|---|---|---|---|---|
| 1080p60 auto | 6.4 | 2.1 / 4.5 | 24.8 | 3.9x |
| 1080p60 no | 27.0 | 22.7 / 4.9 | 47.3 | 1.75x |
| 1080p30 auto | 5.4 | 1.2 / 4.2 | 14.2 | 2.6x |
| real episode (software decode) | 17.3 | 13.3 / 4.5 | 27.6 | 1.6x |

Reading: extra cost of the shared-texture path is roughly +10 to +20 points of one core (1-2.5 % of the whole 8-core CPU), mostly constant per presented frame. The 1080p60 hwdec-auto ratio (3.9x) still exceeds the 1.3x gate; the software-decode cases (1.6-1.75x) are close to it. GPU 3D utilisation is similar (real app 36 % vs spike ~34 % at 1080p60).
